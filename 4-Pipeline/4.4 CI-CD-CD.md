## Подход **CI/CD/CD** (Continuous Integration, Continuous Delivery, Continuous Deployment)

Подход **CI/CD/CD** (Continuous Integration, Continuous Delivery, Continuous Deployment) — это методология разработки программного обеспечения, которая объединяет непрерывную интеграцию, непрерывную доставку и непрерывное развёртывание.


**Непрерывная интеграция (Continuous Integration, CI)** — это практика разработки программного обеспечения, которая предполагает автоматическую сборку и тестирование кода при каждом изменении в репозитории. Позволяет разработчикам быстро получать обратную связь о качестве кода и предотвращать ошибки на ранних стадиях разработки.

![alt text](/image_folder/image-11_1.png)

**Continuous Delivery и Continuous Deployment** — это этапы в методологии CI/CD, которые автоматизируют процесс доставки кода в различные среды, такие как тестовая, staging или production. [habr.com](https://habr.com/ru/articles/888328/)

**Continuous Delivery** («доставка») подразумевает, что код после успешной сборки и тестирования автоматически подготавливается к развёртыванию, но окончательное решение о выпуске принимается вручную. [habr.com](https://habr.com/ru/articles/888328/)

**Continuous Deployment** («развёртывание», «деплой») подразумевает автоматический процесс. Разработчик запустил код в репозиторий — и через некоторое время новая функциональность уже доставлена конечному пользователю

Три наиболее часто используемых этапа: 

- **Build**: на этом этапе выполняются задачи, которые компилируют и/или упаковывают исходный код в пригодный для развертывания формат. 
- **Test**: на этом этапе выполняются задачи, которые запускают автоматические тесты, проверки качества кода и линтеры, а также, возможно, проверки безопасности. 
- **Deploy**: на этом этапе ваш код отправляется в соответствующую среду в зависимости от того, с какой ветвью Git или тегом Git работает конвейер.
  
  Если stages не определено в `.gitlab-ci.yml` файле, этапы конвейера по умолчанию:

- **`.pre`**
- **`build`**
- **`test`**
- **`deploy`**
- **`.post`**
  
  
## Первый пайплайн

```
 stages:
 - build 
 - test
 - deploy

first-job:
  stage: build
  script:
    - echo "first-1-job"

second-job:
  stage: build
  script:
    - echo "second-2-job"

third-job:
  stage: test
  script:
    - echo "third-3-job"
    
fourth-job:
  stage: deploy
  script:
    - echo "fourth-4-job"

fifth-job:
  stage: deploy
  script:
    - echo "fifth-5-job"
    
sixth-job:
  stage: deploy
  script:
    - echo "sixth-6-job"
```

## deploy prod

![alt text](/image_folder/image-16.png)

```
stages:
  - build
  - tests
  - deploy_to_stage
  - acceptance_tests
  - deploy_to_prod

build_job:
  stage: build
  script:
    - echo "Starting build process..."
    - echo "Installing dependencies..."
    - echo "Build completed!"

test_job:
  stage: tests
  script:
    - echo "Running unit tests..."
    - echo "Tests passed!"

deploy_stage_job:
  stage: deploy_to_stage
  script:
    - echo "Deploying to staging environment..."
    - echo "Staging deployment successful!"

acceptance_test_job:
  stage: acceptance_tests
  script:
    - echo "Running acceptance tests..."
    - echo "Acceptance tests passed!"

deploy_prod_job:
  stage: deploy_to_prod
  script:
    - echo "Deploying to production..."
    - echo "Production deployment completed successfully!"
  when: manual  # Деплой в prod только вручную
```
